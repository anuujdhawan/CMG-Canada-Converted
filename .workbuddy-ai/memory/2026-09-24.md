# 2026-09-24

## Fixed: tab/mobile rendered ~72% darker than desktop

**Symptom (user report).** At tab/phone widths the whole page looked far darker
than the desktop rendering, in *both* themes — the light theme hero came out as
dark ink on a muddy dark photo, the dark theme hero was near-black.

**Root cause.** `src/components/layout/MobileMenu.js` — the slide-over drawer is
deliberately always mounted (so Googlebot, which crawls as a smartphone, sees the
nav links). When closed the wrapper only got `pointer-events-none` + `inert`, but
`inert` stops *interaction*, not *painting*. The backdrop button therefore kept
painting its scrim at all times:

```css
/* globals.css:1838 */
body:has(.cmg-template-home) .cmg-mobile-menu__backdrop {
  background: color-mix(in srgb, var(--cmg-template-nav-surface) 72%, transparent) !important;
}
```

The wrapper is `fixed inset-0 z-[1100] min-[1120px]:hidden`, so every viewport
below 1120px (phones **and** tablets) had a permanent `rgba(5,7,11,.72)` veil
over the entire page, above everything.

**Fix.** Fade the backdrop out when closed (component-level, reversible):

```jsx
className={cn(
  "cmg-mobile-menu__backdrop absolute inset-0 h-full w-full cursor-default transition-opacity duration-300 ease-out",
  open ? "opacity-100" : "opacity-0"
)}
```

`opacity-0` (not `invisible`/`hidden`) so the drawer still slides out over 0.28s.

**Verified** on the running dev server with `agent-browser` + pixel measurement
(pinned carousel slide, viewport 390/768/1440, both themes). Backdrop computed
opacity is `0` closed and `1` open; menu-open screenshot still shows the scrim.
Desktop (`≥1120px`) is untouched — the wrapper is `display:none` there.

## Debug technique worth reusing

`npm run build` / `next dev` still can't be *started* in this sandbox, but when
the user already has `next dev` on `localhost:3000` you can drive it directly:

1. `agent-browser set viewport 390 900` → `open http://localhost:3000/` → `eval`
2. `agent-browser eval "document.documentElement.dataset.theme='light'"` switches
   theme instantly (the attribute is the single source of truth; the ThemeToggle
   React state stays stale, so ignore the pill label).
3. `agent-browser screenshot /tmp/x.png`, then measure luminance bands with PIL.
4. To find an invisible overlay, enumerate every element whose background is not
   transparent and whose box covers the region — that's how the 72% scrim surfaced.
5. Probe paint order by injecting `background: rgb(255,0,0) !important` on the
   suspect element: if it renders dark red, something with a large alpha is on top.

Two red herrings ruled out along the way: the `≤880px` `.cmg-hero-carousel__wash`
override (real, but only a secondary factor — after the fix the hero reads
0.55/0.57/0.59 across 390/768/1440 in light theme) and the `hero::before` gradient.

## Fixed: Tailwind canonical-class warnings (Footer.js)

Rewrote 122 non-canonical class tokens into their canonical equivalents —
119 in `src/components/layout/Footer.js` (the reported diagnostics) plus 3 found
by a repo sweep in `src/components/forms/fields.js` (2x `text-[var(--brand-error)]`
→ `text-error`) and `src/components/forms/ConsultationForm.js`
(`before:bg-[var(--brand-gold)]` → `before:bg-(--brand-gold)`). Those three were
the *only* other occurrences of the pattern in `src/`. 64 insertions / 64
deletions; ESLint clean; no structural change.

**Proven zero rendering change**, not assumed:

1. **Pixel diff.** Captured the full footer (viewport 1440x1400 / 420x3200 so the
   whole 1019px / 2885px element is in frame) with the file reverted and re-applied
   between passes, same procedure both sides. All four combos byte-identical
   (max channel diff 0).
2. **Compiled-CSS diff.** Compared emitted rule bodies for every new utility
   against the old ones — identical declarations throughout.
3. **Isolated compile** for the one utility the dev server wouldn't emit.

### Deliberately NOT applied
`text-[.75rem]` → `text-xs` (and `text-[.875rem]` → `text-sm`). In v4 a `text-*`
utility emits `font-size` **and** `line-height`, while an arbitrary `text-[.75rem]`
sets font-size only. `.site-footer__cta` is `12px / 19.8px` (1.65 inherited); `text-xs`
would force `calc(1/0.75)` = 1.3333 and shrink the CTA pills ~3.8px. The reported
diagnostics didn't contain these suggestions either — consistent with IntelliSense
knowing about the side effect.

### Gotchas
- **The dev CSS chunk can go stale.** After editing `ConsultationForm.js` (only
  reachable via the modal / booking page, so not always in the compiled module
  graph), `/_next/static/chunks/_1phab7x._.css` kept serving the *old* selector and
  omitting the new one, with no size change, even after `touch src/styles/globals.css`.
  Footer edits were picked up instantly (always in the layout graph). Verifying via
  the dev chunk alone would have produced a false negative. Use an isolated
  `@tailwindcss/postcss` compile to test whether a utility is real.
- The dev stylesheet keeps previously-seen candidates, so removed selectors linger.
- `@theme inline` maps `--color-*` → `var(--brand-*)`. `--brand-navy-dark`,
  `--brand-logo-bg` and `--brand-gold` have **no** mapping, so they must use the
  `text-(--brand-x)` shorthand, not a named token. Getting this wrong silently
  produces no colour.
- `--tw-duration` accepts bare ms (`duration-180`), and `--spacing` accepts decimals
  (`h-3.75`), so `duration-[180ms]`/`h-[15px]` are canonicalisable exactly.

### Open observation (left for the user to decide)
`Footer.js` L60/L65 use `hover:text-[red]` — pure `#ff0000` vs brand primary
`#f31f3f`. It is the only literal-colour utility anywhere in `src/`, so it looks like
a prototyping leftover. `hover:text-primary` would match the rest of the footer.

### Gotchas worth remembering

- **`.cmg-template-home a { color: inherit }` is unlayered** and beats Tailwind
  text-colour utilities on the `<a>` itself — put colour on an inner `<span>`. Used in
  `HeroProofCard.js`, `ConsultantProfileSection.js` and `Footer.js`.
- **`agent-browser eval` returns strings JSON-quoted** (`"OK"`, not `OK`). A shell
  `[[ $x == OK ]]` comparison silently never matches, so a retry loop built on it never
  breaks. Strip quotes: `| tr -d '"'`.
- **The hero carousel autoplays every 5s**, so "click the dot, wait, screenshot" races
  the timer. Click → verify `aria-current` → shoot immediately, and inject
  `*{transition:none!important}` so the swap is instant.
- **ESLint now gets SIGKILLed (exit 137) in this sandbox**, even on a single small file —
  an environment regression, not a code problem (it was clean earlier the same day).
  Substitute: `@babel/parser` with `sourceType:"module", plugins:["jsx"]` over the
  touched files + `JSON.parse` for the data files. All 13 parsed clean.
