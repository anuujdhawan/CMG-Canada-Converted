## Switched SERP favicon to a multi-size ICO so Google picks it up

User: "i want this icon to be picked by google in serp results as the logo displayed before the website in serp results" — referring to `public/images/favicon.webp`.

**Root cause:** Google updated its favicon docs in August 2026 and now explicitly lists supported formats as **BMP, GIF, ICO, PNG, JPEG, PPM, TIFF**. **WebP and SVG are NOT supported** for SERP favicons — silently ignored. The WebP was correctly linked via `metadata.icons`, but Google would never pick it up.

**Changes:**
- **New file:** `src/app/favicon.ico` — multi-size ICO (16/32/48/64 px, RGBA, ~9 KB). Generated from the 1280×1280 `public/images/favicon_LG.webp` (same red pinwheel logo, crisp at all sizes). Next 16's `app/favicon.ico` file convention auto-emits `<link rel="icon" href="/favicon.ico" sizes="any">`.
- **Edited:** `src/app/layout.js` — removed `icon: "/images/favicon.webp"` and `shortcut: "/images/favicon.webp"` from `metadata.icons` (kept `apple`). Added a comment explaining the format requirement. `npx eslint src/app/layout.js` → clean.
- **New file:** `src/app/icon.png` — 192×192 PNG, same artwork. Next 16's `app/icon.png` file convention auto-emits `<link rel="icon" href="/icon?…" type="image/png" sizes="192x192">`. The skill (`nextjs16-premium-site-build` §12) calls this the modern link "what Google uses"; combined with the ICO, Google has both a root probe and an explicit PNG link in supported formats.
- **Kept on disk (not deleted):** `public/images/favicon.webp` — not in `<head>` anymore; available for any inline use.

**Could not verify here:** full `npm run build` (sandbox `.next` shim). User builds production manually. Confirmed via the Next 16 docs in `node_modules/next/dist/docs/.../app-icons.md` that `app/favicon.ico` is auto-linked as `<link rel="icon" href="/favicon.ico" sizes="any" />`.

**To make Google actually swap to the new icon:** Google's favicon refresh runs on its own schedule (days–weeks). To speed it up: Google Search Console → URL Inspection on the homepage → "Test Live URL" (it will fetch `/favicon.ico`; confirm 200 + `image/x-icon`) → "Request Indexing". The Organization `logo` JSON-LD already points at `/images/logo-large.png` (exists), so the Knowledge Panel logo is unaffected and separate.
