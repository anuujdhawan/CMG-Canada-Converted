## Switched SERP favicon to a multi-size ICO so Google picks it up

User: "i want this icon to be picked by google in serp results as the logo displayed before the website in serp results" — referring to `public/images/favicon.webp`.

**Root cause:** Google updated its favicon docs in August 2026 and now explicitly lists supported formats as **BMP, GIF, ICO, PNG, JPEG, PPM, TIFF**. **WebP and SVG are NOT supported** for SERP favicons — silently ignored. The WebP was correctly linked via `metadata.icons`, but Google would never pick it up.

**Changes:**
- **New file:** `src/app/favicon.ico` — multi-size ICO (16/32/48/64 px, RGBA, ~9 KB). Generated from the 1280×1280 `public/images/favicon_LG.webp` (same red pinwheel logo, crisp at all sizes). Next 16's `app/favicon.ico` file convention auto-emits `<link rel="icon" href="/favicon.ico" sizes="any">`.
- **Edited:** `src/app/layout.js` — removed `icon: "/images/favicon.webp"` and `shortcut: "/images/favicon.webp"` from `metadata.icons` (kept `apple`). Added a comment explaining the format requirement. `npx eslint src/app/layout.js` → clean.
- **New file:** `src/app/icon.png` — 192×192 PNG, same artwork. Next 16's `app/icon.png` file convention auto-emits `<link rel="icon" href="/icon?…" type="image/png" sizes="192x192">`. The skill (`nextjs16-premium-site-build` §12) calls this the modern link "what Google uses"; combined with the ICO, Google has both a root probe and an explicit PNG link in supported formats.
- **Kept on disk (not deleted):** `public/images/favicon.webp` — not in `<head>` anymore; available for any inline use.

**To make Google actually swap to the new icon:** Google's favicon refresh runs on its own schedule (days–weeks). To speed it up: Google Search Console → URL Inspection on the homepage → "Test Live URL" (it will fetch `/favicon.ico`; confirm 200 + `image/x-icon`) → "Request Indexing". ### Hard-won gotchas (do not re-learn these)

1. **`overflow: hidden` breaks `position: sticky`** on any descendant — it makes the ancestor a scroll container. The article shell uses `overflow-x-clip`.
2. **`.cmg-template-home a { color: inherit }` is unlayered CSS** and outranks Tailwind text-colour utilities on an `<a>`. Put the colour on an inner `<span>`.
3. **`body:has(.cmg-template-home)`** in globals.css is what switches the header to the 1220px template pill. A blog page outside `.cmg-template-home` renders unthemed.
4. **Never put a section number badge inside the `<h2>`** — `aria-hidden` spans are still in `innerText`, so extracted headings read `"01What does…"`. Badge is a sibling in a flex wrapper.
5. **Section ids must not start with a digit** — `#2026-targets-at-a-glance` makes `querySelector` throw `SyntaxError`. Renamed to `targets-2026-at-a-glance`.
6. **Tables must stack on phones.** `max-lg:block` on `tr`/`td` drops the *implicit* table roles, so `role="table"/"row"/"columnheader"/"cell"` are declared explicitly. Keeps one real `<table>` for extraction engines.
7. **The TOC must be derived from what renders**, not hand-maintained — a missing entry caused `toc-mismatch` (11 entries vs 12 sections) on all 20 pages. `where-next` and `sources` were the culprits.
8. **`<br />{" "}` is load-bearing.** Removing the `{" "}` welds textContent into `"…route.Then decide."`. Verified empirically: the rendered H1 is `"Research the route. Then decide."` — **the two alleged pre-existing welds in `BlogIndexPage.js` were a false alarm**; a 20-page strict weld scan found 0 genuine welds (only hits were the acronym "eTA").
